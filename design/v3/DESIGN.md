There is no separate `primary` ramp: a monochrome system makes it identical to `neutral` at every step, so only `neutral` is defined. `primary` exists solely as a role (see below).

### Roles

`colors` holds raw material; `roles` names what each is for. **Implementation code references roles, never the numbered scale** — that keeps intent readable and lets a future dark mode swap role targets instead of rewriting every call site. The `roles` block maps 1:1 onto the variables in `ui.pen`, so a design can be transcribed directly.

Note that `surface` is the page background (neutral-50) and `surface-raised` is the lifted plane (pure white). `surface-raised` has no consumers yet — the current design is a single-plane layout.

## Rounded

Steps are derived from what `ui.pen` actually uses, not from a ratio. Pills and small radii sit far apart in practice, so intermediate steps (8px, 16px) are defined rather than rounding everything toward one base.

Radius reads as a ratio, not a difference: 8px → 12px is a 1.5× change and is clearly visible. Do not collapse adjacent steps on the grounds that they are "only 4px apart".

Per-component variation reinforces shape roles — inputs crisper, cards softer.

Per-component intent (resolved in the components block):
- input: `{rounded.sm}` — 12px
- button: `{rounded.full}` — pill; every button in the design is fully rounded
- card: `{rounded.lg}` — 24px
- badge: `{rounded.full}` — pill

Content blocks (code blocks, tables, TOC cards) use `{rounded.xs}` (8px) directly; they are not a component role in this block.

Component-level shape choices are resolved via token references in the `components` block of the frontmatter. Future component additions should follow the same pattern: declare the role (button, card, input, …) and reference a `rounded` token rather than hard-coding a px value.

## Shadow

Shadow is not in the official YAML schema at alpha. Tokens are emitted as CSS variables for direct consumption:

```css
--shadow-sm: 0 1px 2px 0 #00293c0f;
--shadow-md: 0 4px 6px -1px #00293c14, 0 2px 4px -2px #00293c14;
--shadow-lg: 0 10px 15px -3px #00293c1a, 0 4px 6px -4px #00293c1a;
--shadow-xl: 0 20px 25px -5px #00293c1f, 0 8px 10px -6px #00293c1f;
```

Intensity: subtle. Tint `#00293c` (from `oklch(25% 0.08 220)`) at 6/8/10/12% alpha.

**The current design uses no shadows at all.** Depth and grouping are carried by `outline` / `outline-variant` borders instead. These tokens are kept for future use; do not treat their absence in `ui.pen` as an omission, and do not add shadows to match this spec.

Elevation hierarchy: `dropdown` (sm) < `card` (md) < `modal` (lg) < `toast` (xl).

## Usage guidelines

- Reach for a `roles` name first (`on-surface`, `outline`, …). Drop to a numbered `colors` step only when no role fits.
- Primary actions use the `primary` role; on hover shift to `neutral-800`, on active to `neutral-700`.
- Cards take the `card` rounded role and an `outline-variant` border — not a shadow.
- Buttons take the `button` rounded role; separation comes from fill contrast, not elevation.
- Inputs take the `input` rounded role; focus ring follows the interaction-states spec.
- Body text uses the `body` typography role.
- Section spacing: use the `3xl` spacing token between major blocks.
- Stack spacing within a block: use the `md` spacing token.
